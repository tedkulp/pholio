## 2. Bubble Tea v2 API changes that matter for a multi-pane app with overlays

### 2.1 Declarative `tea.View`
`View()` now returns a `tea.View` struct instead of a `string`. Terminal modes are fields on that struct, not program options or commands: `Content`, `AltScreen`, `MouseMode`, `ReportFocus`, `DisableBracketedPasteMode`, `WindowTitle`, `Cursor`, `ForegroundColor`/`BackgroundColor`, `ProgressBar`, `KeyboardEnhancements`, and `OnMouse` ([upgrade guide, "The Big Idea"](https://github.com/charmbracelet/bubbletea/blob/v2.0.10/UPGRADE_GUIDE_V2.md#the-big-idea-declarative-views); struct definition in `bubbletea@v2.0.10/tea.go`). `tea.WithAltScreen()`, `tea.EnterAltScreen`, `tea.HideCursor` and similar options and commands were removed ([upgrade guide, "Removed Program Options" and "Removed Commands"](https://github.com/charmbracelet/bubbletea/blob/v2.0.10/UPGRADE_GUIDE_V2.md#removed-program-options)).

`View.Content` is a plain `string`. The comment on the `Model` interface says the view "can be a string or a [Layer]", but in v2.0.10 the `View` struct has no layer field (`tea.go:62` vs. the struct). Layers are composed in Lip Gloss and flattened to a string (see 2.4).

### 2.2 Key handling
- `tea.KeyMsg` is now an **interface** covering presses and releases. Match on `tea.KeyPressMsg` (or `tea.KeyReleaseMsg`) ([upgrade guide, "Key Messages"](https://github.com/charmbracelet/bubbletea/blob/v2.0.10/UPGRADE_GUIDE_V2.md#key-messages)).
- Field renames: `Type`→`Code` (a rune), `Runes`→`Text` (a string), `Alt`→`Mod` (a bitmask, e.g. `msg.Mod.Contains(tea.ModAlt)`). New fields are `ShiftedCode`, `BaseCode` and `IsRepeat`, plus a `Keystroke()` method. `msg.String()` returns `"space"` for the space bar, not `" "` (same source).
- Paste arrives as its own messages: `tea.PasteMsg{Content}`, `PasteStartMsg` and `PasteEndMsg` (same guide, "Paste Messages").
- **Progressive keyboard enhancements** (the Kitty protocol): when the terminal supports it, Bubble Tea "automatically enables basic keyboard enhancements that disambiguate keys", so combinations such as `shift+enter` and `super+space` become distinguishable and key releases can be detected ([v2.0.0 release notes](https://github.com/charmbracelet/bubbletea/releases/tag/v2.0.0)). You request more through `View.KeyboardEnhancements`, and a `tea.KeyboardEnhancementsMsg` reports what the terminal granted, with `SupportsKeyDisambiguation()`, `SupportsEventTypes()` and similar methods (`bubbletea@v2.0.10/keyboard.go`).
- Bubbles' `key.Binding` is unchanged in spirit. `key.Matches` is now generic: `func Matches[Key fmt.Stringer](k Key, b ...Binding) bool` (`bubbles@v2.2.1/key/key.go:130`). Default keymaps are functions now (for example `textarea.DefaultKeyMap()`), not mutable globals ([bubbles upgrade guide §2c](https://github.com/charmbracelet/bubbles/blob/v2.2.1/UPGRADE_GUIDE_V2.md#2-global-patterns)).

### 2.3 Focus
- Bubble Tea has **no focus manager**. `tea.FocusMsg` and `tea.BlurMsg` refer to *terminal-window* focus and arrive only when `View.ReportFocus = true` (`bubbletea@v2.0.10/focus.go`, and `ReportFocus` doc in `tea.go`).
- Pane focus remains an application concern. Focusable Bubbles expose `Focus() tea.Cmd`, `Blur()` and `Focused() bool`; for example `textarea` at `bubbles@v2.2.1/textarea/textarea.go:784-806` and `textinput` at `textinput.go:262-275`. Focus-dependent styling uses `Styles.Focused` and `Styles.Blurred` (`StyleState`) ([bubbles upgrade guide, Textarea and Textinput](https://github.com/charmbracelet/bubbles/blob/v2.2.1/UPGRADE_GUIDE_V2.md#textarea)).

### 2.4 Compositing and layers (overlays)
- Lip Gloss v2 ships a **cell-based compositor**: `lipgloss.NewLayer(content).X(x).Y(y).Z(z).ID(id)`, nested child layers, `lipgloss.NewCompositor(layers...)`, `Compositor.Render() string`, `Compositor.Hit(x, y) LayerHit` for mouse hit-testing by layer ID, and `GetLayer(id)`/`Refresh()`. A lower-level `lipgloss.NewCanvas(w, h)` exposes `Compose(drawable)`, `Render()` and `CellAt`/`SetCell` (`lipgloss@v2.0.6/layer.go`, `canvas.go`; [README "Compositing"](https://github.com/charmbracelet/lipgloss/blob/v2.0.6/README.md#compositing); [v2.0.0 release notes](https://github.com/charmbracelet/lipgloss/releases/tag/v2.0.0): "Canvas… Layer API… Compositor").
- Layers are drawn in ascending Z order. Hit-testing walks from the highest Z down and ignores layers with an empty ID (`layer.go`, `flatten` and `Hit`).
- Doc drift: the README snippet calls `compositor.Compose(a, b, c).Render()`, but v2.0.6 has no such package-level function. The real API is `lipgloss.NewCompositor(a, b, c).Render()` or `lipgloss.NewCanvas(w,h).Compose(c).Render()` (grep of `lipgloss@v2.0.6`).
- In Bubble Tea the pattern is: build the base pane layout, add overlay layers with a higher Z, `Render()` to a string, and put that string in `tea.NewView(...)` (inference from 2.1 plus the APIs above). `View.OnMouse` lets the view intercept mouse events using geometry from the last render, which pairs with `Compositor.Hit` (`tea.go`, `OnMouse` doc).
- Bubble Tea's new "Cursed Renderer" is "based on the ncurses rendering algorithm". It uses synchronized output (mode 2026) and mode 2027 for correct wide-character and emoji width ([v2.0.0 release notes](https://github.com/charmbracelet/bubbletea/releases/tag/v2.0.0)).

### 2.5 Cursor control
- A real terminal cursor is declared per frame: `View.Cursor *tea.Cursor`, with `nil` meaning hidden. `tea.Cursor` has `Position{X,Y}`, `Color`, `Shape` (`CursorBlock`/`CursorUnderline`/`CursorBar`) and `Blink`. `tea.NewCursor(x, y)` defaults to a blinking block (`bubbletea@v2.0.10/tea.go:365-389`, `cursor.go`; upgrade guide: `tea.HideCursor` → `view.Cursor = nil`).
- `textarea` and `textinput` support either a **virtual cursor** (drawn in the content) or a **real cursor**. `Model.Cursor() *tea.Cursor` returns the real cursor's position *relative to the component*, and `nil` when the component is blurred or the virtual cursor is on. Toggle with the `VirtualCursor` field (textarea) or `SetVirtualCursor(bool)` ([bubbles upgrade guide, Textarea "Cursor"](https://github.com/charmbracelet/bubbles/blob/v2.2.1/UPGRADE_GUIDE_V2.md#textarea); `textarea.go:1751`, `textinput.go:916`).
- The doc comment says "you will almost certainly also need to adjust the offset cursor position per the textarea's position in the terminal": the parent adds the pane's X/Y offset. The comment's example uses a nonexistent `tea.NewFrame`, so read it as `tea.NewView` (`textarea.go:1740-1751`).
- Other Bubble Tea v2 extras: terminal color queries (`tea.RequestBackgroundColor` → `BackgroundColorMsg.IsDark()`), OSC52 clipboard, `tea.WithColorProfile` and `tea.WithWindowSize` (`color.go`, `options.go:160-176`; [release notes](https://github.com/charmbracelet/bubbletea/releases/tag/v2.0.0)).

### 2.6 Bubbles v2 components relevant to an editor
- `textarea` v2.2.1 has selection support (`BeginSelection`/`ExtendSelection`/`EndSelection`/`SelectAll`, `CopySelection() tea.Cmd`, `DeleteSelection`, keyboard selection) plus `PageUp`/`PageDown` bindings, `Column()`, `ScrollYOffset()` and `MoveToBeginning/End` (`bubbles@v2.2.1/textarea/selection.go`, `textarea.go:1783-1854`; upgrade guide).
- `viewport` gains soft wrap, a `LeftGutterFunc` (line numbers), regex highlights, `StyleLineFunc`, horizontal scrolling, and an options-style constructor `viewport.New(viewport.WithWidth(..), viewport.WithHeight(..))` ([bubbles upgrade guide, Viewport](https://github.com/charmbracelet/bubbles/blob/v2.2.1/UPGRADE_GUIDE_V2.md#viewport)).
- There is a new **`tree`** bubble: `charm.land/bubbles/v2/tree`, `tree.New(root *Node, w, h)`, open/close/toggle nodes, a keymap and help, built on `lipgloss/v2/tree` plus a viewport (`bubbles@v2.2.1/tree/tree.go`). It is a candidate for a file-tree pane.
- Width and Height are now getter/setter methods (`SetWidth`/`Width()`) across components (upgrade guide §2b).

## 3. Lip Gloss theming and adaptive colors

- **Colors are `image/color.Color`.** `lipgloss.Color("#ff00ff")` and `lipgloss.Color("21")` are *functions* that return `color.Color`. The `TerminalColor` interface is gone, and `ANSIColor` is an alias for `ansi.IndexedColor` with named constants `lipgloss.Red` and so on ([lipgloss UPGRADE_GUIDE_V2.md, "Color System"](https://github.com/charmbracelet/lipgloss/blob/v2.0.6/UPGRADE_GUIDE_V2.md#color-system)).
- **No global renderer.** `Style` is a plain value. `Render()` always emits full-fidelity ANSI, and downsampling happens at output. Bubble Tea v2 downsamples automatically; standalone code uses `lipgloss.Println` and friends (same guide, "Renderer Removal" and "Printing and Color Downsampling").
- **Adaptive colors are explicit.** `AdaptiveColor`, `CompleteColor` and `CompleteAdaptiveColor` were removed from the root package. The recommended replacements are `lipgloss.LightDark(isDark)(light, dark)` and `lipgloss.Complete(profile)(ansi, ansi256, truecolor)`. A `compat` subpackage keeps v1-style types, but it does blocking global I/O ([lipgloss upgrade guide](https://github.com/charmbracelet/lipgloss/blob/v2.0.6/UPGRADE_GUIDE_V2.md#adaptivecolor-completecolor-completeadaptivecolor); `lipgloss@v2.0.6/color.go:174-265`; [bubbles upgrade guide §4 warning](https://github.com/charmbracelet/bubbles/blob/v2.2.1/UPGRADE_GUIDE_V2.md#4-light-and-dark-styles)).
- **The Bubble Tea pattern** is to return `tea.RequestBackgroundColor` from `Init`. On `tea.BackgroundColorMsg`, rebuild the style set with `newStyles(msg.IsDark())` and pass `isDark` to each Bubble (`help.DefaultStyles(isDark)`, `list.DefaultStyles(isDark)`, `textarea.DefaultStyles(isDark)`, ...) ([lipgloss upgrade guide, "With Bubble Tea"](https://github.com/charmbracelet/lipgloss/blob/v2.0.6/UPGRADE_GUIDE_V2.md#background-detection-and-adaptive-colors); [bubbles upgrade guide §4](https://github.com/charmbracelet/bubbles/blob/v2.2.1/UPGRADE_GUIDE_V2.md#4-light-and-dark-styles)). The `LightDark` doc says this message is "received whenever the background color changes" (`color.go:184-190`).
- Helpers include `lipgloss.Alpha`, `Darken`, `Lighten`, `Complementary`, `Blend1D` and `Blend2D` (`color.go:292-345`, `blending.go`).
- **Theme files:** neither Lip Gloss nor Bubbles has an API for loading styles from a file (no JSON/TOML/YAML in `lipgloss@v2.0.6` README or source). The Charm conventions are:
  - **Themes as Go functions of `isDark`.** huh v2 uses `type ThemeFunc func(isDark bool) *Styles`, with `ThemeCharm`, `ThemeDracula`, `ThemeCatppuccin` and others (`charm.land/huh/v2@v2.0.3/theme.go:15-285`). Bubbles uses `DefaultStyles(isDark bool)`.
  - **Glamour's JSON style files** are the only first-party file-loaded theme format. They cover *markdown rendering* styles: `glamour.WithStylesFromJSONFile(path)`, `WithStylesFromJSONBytes`, `WithStylePath` (a built-in name or a file path), and the `GLAMOUR_STYLE` env var through `WithEnvironmentConfig()`. Built-ins ship as JSON (`dark`, `light`, `dracula`, `tokyo-night`, `pink`, `ascii`, `notty`) (`charm.land/glamour/v2@v2.0.1/glamour.go:109-165`, `styles/*.json`, README). Glamour v2 **removed `WithAutoStyle()`**, and the default is `"dark"`, so callers pick light or dark themselves ([glamour UPGRADE_GUIDE_V2.md](https://github.com/charmbracelet/glamour/blob/v2.0.1/UPGRADE_GUIDE_V2.md)).
  - In short, no established Charm pattern loads an *app UI* theme from a file. An app defines its own schema (hex strings → `lipgloss.Color`), optionally with light and dark variants resolved through `LightDark`, and builds `lipgloss.Style`s from it.

## 4. Testing: what Charm recommends

- **teatest** is Charm's own testing helper. It is still **experimental** and lives in `x/exp`, now with a v2 module: `github.com/charmbracelet/x/exp/teatest/v2`, untagged and consumed as a pseudo-version ([teatest v2 source](https://github.com/charmbracelet/x/tree/main/exp/teatest/v2); `go mod download` result above). The official blog post "Writing Bubble Tea Tests" (Carlos Becker, 2023-05-08) says: "This is an experimental, work in progress library, hence the `github.com/charmbracelet/x/exp/teatest` package name" ([charm.land/blog/teatest](https://charm.land/blog/teatest/)).
- The v2 API runs a real `tea.Program` with in-memory I/O through `NewTestModel(tb, model, WithInitialTermSize(w,h), WithProgramOptions(...))`, which defaults to 80×24. It provides `Send(msg)`, `Type(s)` (sends `KeyPressMsg` per rune), `WaitFor(tb, tm.Output(), cond, WithDuration, WithCheckInterval)`, `Quit()`, `WaitFinished`, `FinalModel(tb)` for state assertions, `FinalOutput(tb)`, and `RequireEqualOutput(tb, out)` for golden files under `testdata/*.golden`, regenerated with `go test ./... -update` (`teatest/v2@…/teatest.go`, `app_test.go`; [blog](https://charm.land/blog/teatest/)).
- The blog's setup advice is to force a fixed color profile so golden files match in CI, and to add `*.golden -text` to `.gitattributes` ([blog](https://charm.land/blog/teatest/)). The blog's `lipgloss.SetColorProfile(termenv.Ascii)` is v1 API. In v2 the equivalent is `teatest.WithProgramOptions(tea.WithColorProfile(colorprofile.Ascii))` (`bubbletea@v2.0.10/options.go:155-163`; v1 call removed per [lipgloss upgrade guide](https://github.com/charmbracelet/lipgloss/blob/v2.0.6/UPGRADE_GUIDE_V2.md#renderer-removal)).
- Bubble Tea v2 itself promotes `tea.WithWindowSize(80, 24)` so tests can "set the initial terminal size" without mocking a terminal ([v2.0.0 release notes](https://github.com/charmbracelet/bubbletea/releases/tag/v2.0.0); upgrade guide "New Program Options").
- Other x packages: `github.com/charmbracelet/x/exp/golden` (v0.1.0) backs `RequireEqualOutput`. `github.com/charmbracelet/x/vt` is a virtual terminal emulator (`vt.NewEmulator(w,h)`, `Write`, `String()`, `CellAt`) that can turn raw program output into a screen grid (`x/vt@…/emulator.go:80-288`). Nothing official presents vt as a testing tool; this is an option, not a recommendation.
- No newer official testing framework exists. Issue [#1654 "Proposal: Testing framework for Bubble Tea applications"](https://github.com/charmbracelet/bubbletea/issues/1654), opened 2026-04-01, was still open with no maintainer response visible when fetched.
- Caveat (inference): teatest v2 output is the Cursed Renderer's *incremental* byte stream, cursor moves and diffs included, so golden files of full program output are sensitive to renderer changes between Bubble Tea patch releases. Driving `Update` directly and asserting on `View().Content` (pure model tests), or replaying output through `x/vt`, yields more stable assertions.

## Implications for pholio

1. **Start on v2 directly.** Use `charm.land/bubbletea/v2` (v2.0.10), `charm.land/bubbles/v2` (v2.2.1), `charm.land/lipgloss/v2` (v2.0.6) and, for markdown preview, `charm.land/glamour/v2`. Go ≥ 1.25 is required, and 1.27 is installed. Do not mix in v1 `github.com/charmbracelet/*` imports.
2. **Overlays come from the Lip Gloss compositor.** Lay out panes with `JoinHorizontal`/`Place`, put modal and palette layers above them in Z, render to a string, and return it from `tea.NewView`. Give layers IDs so `Compositor.Hit` handles mouse routing.
3. **Focus is ours to own.** A small focus-ring model in the root `Update` routes `KeyPressMsg`s to the focused pane and calls `Focus()`/`Blur()` on Bubbles. Global keys use `key.Binding` and `key.Matches`. Kitty disambiguation makes bindings like `shift+enter` viable, but they need fallbacks for terminals without the protocol.
4. **Use the real cursor.** Set the editor `textarea` to a real cursor and copy `m.editor.Cursor()` into `View.Cursor`, adding the pane's screen offset (and hiding it while an overlay has focus). The built-in textarea selection, `CopySelection` and the `viewport` gutter cover a lot of v1 editor needs. Check whether textarea scales to large documents before committing to it.
5. **Themes: define our own file schema.** No Charm convention exists for UI theme files. Define a small TOML or JSON theme (named hex colors, optional light/dark pairs) and map it into a `Styles` struct built with `lipgloss.LightDark(isDark)`. Rebuild on `tea.BackgroundColorMsg`, and pass `isDark` to each Bubble's `DefaultStyles`. Glamour preview styles can load from JSON files natively (`WithStylesFromJSONFile`), and the pholio theme could point at or embed one.
6. **Testing:** most tests should be pure model tests (call `Update`, assert on state and `View().Content`). A thin layer of teatest v2 end-to-end tests with `WithInitialTermSize` + `tea.WithColorProfile(colorprofile.Ascii)` and `*.golden -text`. Pin teatest's pseudo-version in go.mod, because it is experimental and untagged.
